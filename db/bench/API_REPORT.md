## Выводы

> Раздел написан вручную по этому прогону; `KassirERP.ApiBench` его не генерирует.

- **Бэкенд добавляет к скану ≈ 0.2 мс** (p50 +0.19…0.21, p95 +0.27…0.29). Из них ≈ 0.16 мс — HTTP и проверка JWT (`/auth/me` без базы), остальное — маршрутизация, DI и JSON. Скан через API: p50 0.9 мс, p99 2.3 мс.
- **К поиску бэкенд добавляет 0.5–0.9 мс** (p50) — около 1 % времени. Время поиска определяет Postgres.
- **Между Postgres и Npgsql ≈ 0.5 мс** — сеть с Windows до контейнера Docker (WSL) и сетевой обмен драйвера. На сервере, где API и Postgres рядом, этого будет меньше. Отдельной команды `set_config` нет: `TenantDb` отправляет её одним пакетом с запросом.
- **Внимание: поиск в самом Postgres сейчас 47–60 мс, в REPORT.md было 37–44.** План — `Seq Scan` по всем товарам базы: индекс trigram не используется. А товаров стало 61 293 против 55 001: конкурентный тест S4 добавил 6 293 товара с «телефонов». Время поиска растёт линейно с числом товаров. Два из трёх запросов уже выше цели ТЗ < 50 мс. Это нужно решить до живых клиентов; индекс по договорённости не трогал.
